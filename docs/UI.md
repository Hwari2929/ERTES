# UI 지침 — 읽게 하지 말고 보이게

ERRANTEs 의 화면은 '게임 판'이다. 판정 기준은 **문장이 있느냐가 아니라, 그 화면에서 비교 · 판단해야 하는 정보(수치 · 조건 · 행동)를 문장 속에 묻었느냐**다.

## 1. 원칙

1. **독립 정보는 '이름 + 값'으로 나눈다.** 한 문단에 자원 · 예상치 · 규칙이 같이 들어가면 쪼갠다. (예: 보유 크레딧 · 다음 전투 이자 · 만기 정산 → 칩 3개)
2. **정보는 그것이 작용하는 대상 옆에 둔다.** 슬롯 수는 슬롯 옆, 보장 진열은 진열대 옆, 진행도는 진행 바 옆.
3. **단계형 효과는 '지금 → 다음'부터.** 현재 단계 효과와 다음 단계에서 바뀌는 값을 먼저 보이고, 바뀌는 수치는 `a → b` 로 나란히 둔다. 전체 단계표는 그 뒤.
4. **성장 · 자원은 게이지 + 근거 분해.** 게이지(현재) · 예상 증가량(다음) · 계산 근거(기본 몫 · 장비 몫 · 배율)를 따로 칸으로.
5. **화면 머리는 '제목 + 이 화면의 상태 칩 1줄'.** 규칙 설명(조합법 · 획득처 · 회수 규칙 등)은 머리에 쓰지 않는다 → 교범 · 접힌 도움말 · 작은 도식으로.
6. **일반 규칙과 이 대상의 정보는 섞지 않는다.** 기물 상세에 유형 공통 규칙이 필요하면 접힘 / 교범 연결로.
7. **조작 확인은 대상 옆에서.** 화면 전체를 가리는 창 대신 대상 옆 작은 팝업 (✕ / ✓ 아이콘만, Esc = ✕). 결과 미리보기가 꼼수가 되면(무작위 결과) 확정 뒤에 공개.
8. **연출은 실제 상태 변화에 붙인다.** 보상 공개 · 공명 상승처럼 값이 바뀌는 순간에, 바뀌는 대상 위에서.
9. **짝 조작은 같은 자리에서.** 숨기기 ↔ 보이기, 접기 ↔ 펼치기, 켜기 ↔ 끄기처럼 서로 되돌리는 단추는 상태가 바뀌어도 **같은 위치 · 같은 크기**에 남는다. 되돌리는 단추를 다른 쪽으로 보내거나, 스크롤에 밀려 화면 밖으로 사라지게 두지 않는다 (필요하면 sticky 로 고정). 누른 자리에서 바로 다시 누르면 원래대로 돌아와야 한다.
10. **강조는 상태의 의미에 따라 나눈다.** 테두리 굵기는 다른 칸 · 기물 토큰과 맞추고, 굵기로 강조하지 않는다. 일반 지형과 지속되는 선택은 **정적으로** 표시한다. 선택 · 사용 대기 · 유효 대상 · 효과 범위 · 위험을 서로 다른 표현으로 구분하며 색만으로 구별하지 않는다 (모양 · 아이콘 · 선 종류를 함께). **반복 애니메이션은 임박한 위험이나 진행 중인 작업처럼 시간에 따라 주의가 필요한 상태에만** 쓰고, 선택 · 결과 발생에는 짧은 전환 효과만 쓴다 (prefers-reduced-motion 이면 생략). 예외: 바 무대 이모티콘(말 대신 하는 감정 표현)은 사용자가 정한 캐릭터 연출이라 반복 움직임을 쓴다 (`20-bar.css` `.bar-emo.on[data-e]`, 움직임 줄이기면 끈다).

    | 상태 | 표현 |
    |---|---|
    | 일반 지형 | 종류별 무늬 · 색 · 얇은 경계, 정적 |
    | 상세를 보는 대상 | 선택색의 일정한 경계 · 옅은 면, 정적 (고를 때 짧은 전환) |
    | 사용 대기 중인 도구 (장비 · 소모품) | 선택 표시 + `지뢰 배치 중` 같은 행동 칩 + 취소 |
    | 놓을 수 있는 영역 | 약한 면, 정적 |
    | 가리킨 기준점 | 가장 선명한 설치물 실루엣 · 조준점 |
    | 효과 범위 | 옅은 면 또는 점선 (기준점과 다른 표현) |
    | 놓을 수 없음 | 그 자리에 금지 표시 + 짧은 이유 |
    | 곧 일어날 위험 | 경고색 + 시간에 맞춘 점멸 |

    - 예외: **테마 바탕층의 별빛** (갤럭시 별 · 메트로 창밖 별빛, `ui/themefx.ts`) — 정보가 없는 맨 아래 장식층이라 아주 느리게 반짝이는 것을 허용한다. 내용 위로 올라오지 않고, 전투 중에는 멈추며, 설정 '효과'의 줄이기 · 끄기로 멈춘다.
11. **보는 대상과 쥔 도구를 나눈다.** 상세를 읽으려고 고른 것(기물 · 적 · 지형)과 다음 누름에 쓰일 도구(장착할 장비 · 놓을 소모품 · 크레인)는 다른 상태다. 도구를 쥐면 무엇을 쥐었는지 칩으로 보이고, 다음 누름의 결과(장착 · 설치 · 이동)가 미리 보여야 한다. 범위 · 모드가 중요한 도구는 터치에서 첫 탭 = 후보 표시, 같은 자리 재탭 = 확정.
12. **상세 패널은 '이름 · 상태 → 핵심 성질 → 할 수 있는 행동 → 세부 규칙' 순서.** 같은 정보를 칩과 표로 반복하지 않는다. 바꿀 수 있는 것(접기 · 옮기기 · 시작 상태)은 세부 규칙보다 앞에 둔다.
13. **상태색은 등급 · 분류색과 겹치지 않는다.** 등급색(재료 흰색 · 고급 초록 · 희귀 파랑 · 전설 빨강 · 고유 장비 보라 — 기물 전용 · 캠페인 장비는 전설급이어도 보라)이나 진영색을 '가능 · 선택' 같은 상태 표시에 쓰지 않는다. **선택한 장비 · 소모품 = 그 토큰 바로 바깥의 호박색 실선 테두리** (간격 없이 붙여서, 필요하면 선택자만 굵게). 그래서 전설 등급은 호박 · 노랑이 아닌 붉은 계열을 쓴다. 증강 등급도 같은 색 하나로 고정한다: 일반 = 흰색 · 희귀 = 파랑 · 전설 = 빨강 (전역 증강 카드 · 보유 목록 · 도감, 갤럭시 · 메트로 공통 `--gc` · `--tc` — 일반 카드마다 색상을 무작위로 주지 않는다, 2026-11-06). 점선은 '범위 · 미리보기'에만 쓰고 선택 강조에 쓰지 않는다.
14. **도구를 쥐면 '못 받는 것'을 흐린다.** 장비 · 소모품을 눌러 쥐었을 때와 끌고 있을 때는 같은 표현이다: 받을 수 없는 대상(적 · 받을 수 없는 아군 · 다른 소모품 등)을 포탑처럼 흐리게 하고, 받을 수 있는 대상에 색 테두리를 새로 두르지 않는다. 받는 순간의 결과(장착 · 조합 · 교체)는 가리킨 대상 위에서만 보인다.
15. **팝오버는 원래 자리 옆, 판을 가리지 않게.** 보관함 · 장비 팝오버는 그 물품 옆(보드 반대쪽)에 띄운다. 옆 자리가 없으면 (태블릿 세로) 보드 칸 대신 보드 위 머리 자리(상단 바 · 보드 머리줄)에 겹쳐 띄우고, 하단 시트로 보드 칸을 덮지 않는다. 팝오버가 보여 주는 정보를 화면 머리 칩 · 보드 위 행동 칩에 또 쓰지 않는다 — 팝오버가 열려 있으면 칩을 숨기고 그만두는 단추(`취소`)는 팝오버에 둔다. 머리에 꼭 남겨야 하는 '하는 중' 표시는 배치를 밀어내지 않게 겹쳐 띄운다 (absolute).
18. **겹쳐 띄운 것은 누름을 아래로 넘기지 않는다.** 보드 위 행동 칩 · 팝업처럼 다른 대상 위에 겹친 것은 글자 · 빈 곳을 눌러도 그 밑의 칸 · 기물에 누름이 가지 않는다 (밑에 놓이거나 선택되면 안 된다). 대신 작게 만들어 덜 가린다.
19. **그림 위 장면은 일러스트의 색 덩어리를 지키고, 바 · 계약 흐름은 '청사진 레터프레스' 한 재료로 만든다.** 눈을 가늘게 뜨고 봤을 때 화면에 색 덩어리가 셋(에란테스 바: 창밖 파랑 · 인물 회색 · 선반 호박) 보여야 한다 — UI 는 그것을 덮지 않는다. 배경 전체를 어둡히거나 흐리지 않고(비네트 10% 이하), 그림자는 판 **바로 뒤**에만. 빈티지의 기준은 **빅토리안 활판 메뉴판(70) + 19세기 천문 항해 도면(30)**이고, 바탕은 크림이 아니라 **한색 종이**다. 세 층 — 종이(`--lp-paper` 파우더 블루, L65) · 프러시안 청사진(`--lp-bp`, L25) · 네이비 띠(`--lp-navy`, L10) — 를 금(`--lp-au` 밝은 가는 선 + `--lp-au-lo` 어두운 굵은 선, **선과 점으로만**, 면으로 칠하지 않는다)이 가로지른다. 종이 위 잉크는 네이비, 띠 · 청사진 위 글씨는 청백(`--lp-cw`). 전표는 청색 카본지(`--lp-carbon` + 보랏빛 먹지 잉크 `--lp-cink`, 살짝 번짐 · 절취선). 도장(`--lp-stamp`)은 한색 위에서 튀므로 면적 최소. 크림(`--lp-cream`)은 회중시계 법랑 · 별점 중심 같은 '빛의 끝'에만. **금지**: 갈색 · 크림 면 · 시안 홀로 · 글로우 · 스캔라인 · 흰 별 · 금 면 · 둥근 모서리 8px 이상 · 알약 칩 · 전역 어둡힘 · 반복 애니메이션. 이 재료는 **바 허브와 계약 흐름(종이가 실제 사물인 곳)에만** 쓰고, 그늘 장면이 끝나면 명부 · 지도부터는 게임 토큰으로 돌아간다 (카본 영수 증서 칩 하나만 따라간다).
    - 어휘 9개 밖의 장식을 새로 만들지 않는다: 종이 결(`.lp-grain` 4~6%) · 네이비 띠(`.lp-band`, 띠 안에만 금 별점 `.lp-stars`) · 가는 괘선 두 줄 액자(`.lp-frame`) · 금 괘선(`.lp-rule` · `.lp-rule-thin`) · 점선 리더(`.lp-dots`) · 네이비 라벨(`.lp-lbl`) · 청사진 모눈(`.lp-bp`) · 카본 절취선(`.lp-carbon`) · 금 선 그림 두 겹(`.lp-lo` 굵은 획 아래 + `.lp-hi` 가는 획 0.5 위, 벨 · 체인 · 회중시계). 리본 · 필리그리는 쓰지 않고, 스와시 · 마름모 괘선은 네이비 표지에만 (속지 종이는 가는 괘선 액자뿐).
    - 예외: **바 주문 스포트라이트** (2026-11-03 사용자 결정) — 주문 표시를 누른 동안만 배경 · 다른 손님 · 그 잔을 조금 어둡게 하고(배경 30% 덮개 · 다른 손님 밝기 50%), 그 손님에게 위에서 은은한 호박색 빛(불투명도 0.15)을 비춘다. 빛은 흐리게 번지고(블러) 위는 거의 비지 않으며 아래로 갈수록 서서히 밝아지고, 천천히 켜진 뒤 숨 쉬듯 느리게 밝기가 바뀐다 (반복 움직임 예외, 움직임 줄이기면 멈춤). ✕ 나중에 · ✓ 받기는 말풍선 바로 오른쪽 바깥. 대사 말풍선(이모티콘 제외)은 늘 그 인물의 머리 위에 뜨고, 그림을 가리지 않는다 — 스탠딩 그림의 실제 맨 위(머리카락 · 든 물건까지, 그림마다 한 번 재서 둔다 `bar.ts` `artTop`)보다 위에, 말풍선 폭 안에 들어오는 옆 사람 그림보다도 위에 둔다 (2026-11-05 사용자). 낮은 가로 화면은 말풍선을 넓게 써서 줄 수를 줄인다. 받기 · 나중에를 고르면 바로 걷힌다 (`ui/bar.ts` `focusOrder`).
    - 예외: **바 무대 말풍선 · 이모티콘 말풍선은 흰 바탕 · 검정 글씨** (2026-11-03 사용자 결정, 글자 한 단계 크게 — 대사 `--fs-lg` · 이름 `--fs-sm`). 이름 색 · 이모티콘 색은 검정 쪽으로 조금 눌러 흰 바탕에서 읽히게 한다 (`20-bar.css` `.bar-bub` · `.bar-emo`).
    - SVG 에는 평평해도 되는 물건(전표 · 벨 · 체인 · 회중시계 · 궤도 선 그림)만 맡긴다. 가구 · 조명 · 인물은 그림(배경 · 스탠딩)을 쓰고 벡터로 그리지 않는다. 인물은 종이 **뒤**에 선다 (에이든은 전표 뒤).
    - 글자 셋: 제목 · 항목 = 세리프(`--f-serif` Gowun Batang, 자간 .14~.3em), 라벨 = 고딕(`--f-body`), 수치 · 전표 = 한글 고정폭(`--f-slip`), 서명 = 펜(`--f-pen`, 한글 '레이첼'). 활판 눌림은 종이 위 글자에만(`text-shadow` 흰 1px 아래 + 검정 1px 위).
    - 고름 = 그 줄이 네이비 띠로 반전 + 왼쪽 금 별점 하나(`.lp-row.on`). 단추 · 놋쇠 손잡이 · 체크 상자는 없다. 단추가 꼭 필요하면 네이비 위 금 테(`.lp-btn`).
    - **레터프레스는 종이 사물에만**: 차림표 · 전표 · 표지 · 길 안내 띠처럼 실제로 종이 · 인쇄물인 것만 이 재료로 만든다. 말풍선 · 이름표 · 칩 같은 게임 UI 는 어느 화면에서든 게임 토큰 그대로 (`--panel` 바탕 · `--line` 테두리 · `--r-lg`, 이름표는 `--overlay` 알약). 종이 결 · 파우더 블루 · 금 테 · 굵은 점선을 말풍선에 쓰지 않는다. 무대 밖 화자(레이첼) 말풍선은 같은 모양에 꼬리만 없다.
    - 메뉴판 표지는 네이비가 중심이다: 네이비 바탕 + 금 액자(바깥 두 톤 + 안쪽 가는 선) · 모서리 스와시 · 마름모 괘선 · 별자리 하나, 가운데 간판 = 동판 필기체(`--f-sign` Pinyon Script)로 가로로 쓴 'Errantes' 를 아래에서 위로 읽게 돌려 세운 것 (책등 방향) (금 두 톤 글씨, 한글 세로쓰기 · 굵은 명조 간판은 쓰지 않는다). 표지에는 수 · 상태를 쓰지 않는다 (전표 번호 · 의뢰 수는 전표와 속지에).
    - 길 안내는 메뉴판 표지의 세로 네이비 띠(`.bar-nav`): 장소마다 한 줄, 가리키면 그 사물이 밝아진다. 명판 · 버튼 줄 없음.
20. **목록은 메뉴판처럼 읽힌다.** 큰 글자 = 플레이어가 고르는 말(표준 · 성과급 · 담보), 작은 글자 = 세계의 말(법무부 · 쉬움 · 위험 3). 로어 이름이 고르는 말을 이기지 않게 한다. 한 줄에는 수 + 대표 1개(`제1~6조 · 적 피해 ×1.5`)만 두고 전문은 문서(전표 · 정보 판)에 — 같은 내용을 두 군데 쓰지 않는다. 주 항목(의뢰 제목)은 잘리지 않게 두 줄까지, 부제가 한 줄로 줄어든다. 도박 같은 선택지는 기대값을 세울 범위를 대상 옆에 둔다(`싯가 · 보수 +10~30%`).
21. **사물에 설명 라벨을 붙이지 않는다.** '의뢰 · 약관을 고르면' 같은 설명이 사물 밑에 붙으면 사물이 아니라 버튼이 된다 — 상태는 사물의 모양(느슨한 줄 ↔ 팽팽한 줄, 꺼진 전구 ↔ 켜진 전구)으로, 할 일은 인물의 말(에이든 말풍선)로. 아직 못 고르는 칸은 회색 목록으로 다 보이지 말고 숨겨 두었다가, 열리는 순간 나타나게 한다 (열림이 작은 보상). 종이 위의 칸이면 있던 종이의 글자를 좁혀 자리를 만들지 말고 **새 종이 한 장이 밀려 들어온다** (담보 약관 → 특약 차림표, 각도 ±3° 무작위). 잠깐 덮는 종이(메뉴에 없는 의뢰)는 아래에서 튀어나와 다음에 고를 칸(약관)은 거의 덮지 않고, 아래로 쓸어 내리거나 Esc 로 빠진다 (손잡이 막대 같은 휴대폰 UI 는 두지 않는다 — 종이다).
22. **반복되는 의식은 처음에만 길다.** 로그라이트는 같은 흐름을 수십 번 지난다. 두 번째부터는 단골 경로(`늘 하던 대로` · 직전 선택 복제)와 압축(설명문 생략 · 한 번에 넘어가는 단추 · 연출 2초대)을 준다. 기록은 쌓인다(전표 번호 = 서명한 계약 수) — 첫 번째와 열 번째가 같으면 안 된다.
23. **보드 위 아군은 모두 같은 토큰이다.** 소환물 · 시너지 소환물(근위기사) · 공왕 무휼도 기물 토큰(초상 · 공명 등급 칸 · 유형 아이콘 · 장비 칸)을 그대로 쓴다. 소환물은 장비가 없으니 장비 칸 줄만 빼고(공명 등급 칸 자리 = 소환물 표시), 무휼은 전용 장비가 있으니 3칸 그대로(옮길 수 없을 뿐). 점선 · 축소 같은 별도 모양을 만들지 않는다.
24. **판단을 바꾸는 선택은 고르기 전 · 고른 뒤 · 기록에 모두 보인다.** 더 위험한 선택지(예: 담보 약관)는 고르기 전부터 다른 표식(해골 + '위험' 도장 · 붉은 눈금 — 이름을 표식 안에 되풀이하지 않는다), 고르면 실제로 감수하는 것과 받는 것을 나눈 구획이 도면(표시기)에 뜨고, 영수증(전표)에도 짧게 남는다. 메뉴판 같은 연출 화면에는 배율 · 수치를 쓰지 않고(특약도 '적의 체력이 증가합니다' 한 줄 + 단계 체크칸), 수치는 도면 · 환경 탭 같은 참조 자리로 보낸다.
25. **종이 위의 선택은 종이에 실제로 할 수 있는 표시로 한다.** 차림표 같은 종이 사물에서 고른 줄을 네이비 띠로 칠하거나 마름모를 붙이지 않는다 — 이름 ‥ 선 ‥ 체크칸에 펜으로 긋는 체크(한 획, 손으로 그은 듯)만. 배타적인 선택을 바꾸면 앞 체크를 지운 뒤 새 칸에 긋는다. 표시기(도면)처럼 화면인 사물만 화면식 전환(꺼졌다 켜짐)을 쓴다.
26. **그림(SVG · 캔버스)에 명암을 넣지 않는다 (요청이 없으면).** 밝은 줄 · 어두운 줄 두 겹으로 반을 가르는 하이라이트, 유리 반사, 가장자리 그늘 같은 명암은 넣지 않고 한 색 면 · 선으로 그린다. 깊이는 크기 · 진하기 · 흐림으로만. 화면 전체를 번쩍이는 연출도 쓰지 않는다 (섬광은 그 자리에서만).
    - 예외: **바 잔 그림** (2026-11-04 사용자 결정) — 잔 일러스트는 음료와 따로 한 겹으로 color-dodge 0.6 으로 배경과 섞고, 층 경계 · 액면은 잔 그림의 시점에 맞춰 타원 호로 그린다 (`ui/drinkart.ts`, docs/BAR_OPS.md). 음료 층 자체는 여전히 명암 없는 한 색 면.
27. **장면 전환은 이어 붙이지 않고 이어 움직인다.** 다음 장면으로 넘어갈 때 앞 장면을 통째로 지우고 새 화면을 그리지 않는다 — 주인공 사물(전표 · 메뉴판 · 출력기 · 램프 빛)은 그 자리 · 그 각도 · 같은 종이 · 같은 내용에서 이어 움직이고, 조명은 서서히 꺼지며, 남는 사물은 어둠에 잠긴다. 앞 장면의 말풍선 · 상황 줄 · 단추는 툭 사라지지 않고 옅어지며, 새 장면의 대사 · 단추는 시선 전환이 끝난 뒤에 나타난다(같은 자리에서 다른 단추로 바꿔치기하지 않는다). 연출 층은 다음 화면 위에서 마저 끝나고 걷힌다 — 배경이 바뀌는 순간 같이 사라지지 않는다 (계약 → 명부: 표시기 화면이 시야를 채우고 꺼진 뒤 은하가 걷히며 카드가 떨어져 놓인다).
28. **가짜 진행 바를 두지 않는다.** 읽을 것이 없는 단일 HTML 에서 시간으로 차는 '로딩' 바는 금방 들킨다. 진행은 실제로 세는 단위(예: 브리핑 상태문 줄 수 — 줄마다 한 칸, 마지막 줄이 끝나면 100%)에 묶고, 누르면 남은 칸이 한꺼번에 찬다. 이름도 '로딩'이 아니라 세계의 말(`브리핑 수신`). 흐르는 글의 인물은 곧 나올 대상(이번 후보 기물)에서 뽑아, 다음 화면이 '방금 들은 사람들이 도착했다'로 읽히게 한다. 같은 흐름에서 같은 줄을 되풀이하지 않는다. 줄은 한두 줄이면 충분하다 — 누가 뭘 하는지 다 보여 주려 늘이지 않고, 준비가 끝나면 빠르게 넘어간다 (티커 줄은 서로 눌려 겹치지 않게 flex: none). 장면 사이에 잠깐 뜨는 알림(예레나의 브리핑 알림)은 토스트다: 아이콘과 흔들림으로 '알림'임을 알리고, 다음 장면에서 잠깐 남았다가 사라진다. **기기 화면 속 UI(상태줄 · 토스트)는 그 기기의 규격으로 그린다** — 보드 위 태블릿이면 태블릿 화면을 시야 크기로 볼 때의 치수(브리핑 화면의 상태줄 · 토스트와 같은 치수)를 카메라 배율만큼 줄여 화면에 처음부터 그려 둔다 (`.ct-os`, ui/contract.ts `osFit`). 멀리서는 흔들림만 보여도 충분하고, 기기 UI 가 다음 화면에서 갑자기 생기지 않는다.
29. **맥락 그림은 상자에 가두지 않고 배경으로 깐다.** 장식 · 맥락 그림(전장 그림 등)을 화면 머리에 상자 한 줄로 따로 쌓으면 그만큼 본문(카드)이 눌린다. 그림은 화면 위쪽을 가로질러 카드 윗단까지 그대로 보이고, 그 아래로 바탕에 옅어지게 깐다 (명부: 고정 배경 300px, 아래 160px 가 옅어짐). 그 위 머리는 첫 줄 = 맥락(「의뢰」 전장) · 둘째 줄 = 할 일 제목(`계약 기물 4명을 선택하세요`), 오른쪽 = 판단에 쓸 정보(자주 나오는 적 · 유리한 시너지)를 이름 + 값으로 · 상세 보기. 글자 쪽만 어둡게 하고 그림 전체를 덮지 않는다.
30. **덮는 창에는 언제나 닫기(✕)가 머리 오른쪽 끝에 있다.** 미리보기 · 전체 상세처럼 화면을 덮는 창은 모드(영입 전 미리보기 · 보유 기물)와 상관없이 같은 자리에 ✕ 를 둔다 — Esc · 바깥 누르기만으로 닫히게 두지 않는다 (휴대폰에는 Esc 가 없다). 그 창을 여는 단추도 호버 때만 드러내지 않고 카드 오른쪽 위 빈 자리에 확대 아이콘으로 늘 둔다 (글자 단추로 카드 아래를 채우지 않는다).
31. **바의 빈티지 문법은 태블릿 앞에서 끝난다.** 레터프레스 재료(명조 `--f-serif` · `--f-paper`, 필기체, 고정폭 전표 글꼴 `--f-slip`, 크림 · 카본 · 도장 색 `--lp-*`, 금 테 · 종이 결 · 천문 도식)는 바 · 계약 보드의 **종이 사물**(차림표 · 특약 · 전표)에만 쓴다. 태블릿(표시기)은 바의 소품이 아니라 지휘관의 기계라 보드 위에 놓여 있을 때부터 고딕 · 시인성 토큰 · 무광 흑연 몸체로 그린다 (금 테 · 명조 · 넓은 자간 없음). 카메라가 태블릿 화면에 들어간 순간(브리핑 수신)부터 계약 기물 선택 · 런 전체는 인게임 고딕(`--f-body` · `--f-display`)과 시인성 토큰(`--c-text` · `--c-text-2` · `--c-good` · `--c-bad` · `--panel` · `--line`)만 쓴다 — 런 안의 영수 증서 칩도 일반 칩이다. 이어짐은 태블릿의 청사진 모눈(같은 자리 · 같은 간격)으로만 잇는다.
32. **상태 · 페이즈가 바뀔 때 아무것도 순간이동하지 않는다.** 한 장면에서 다음 장면으로 이어지는 것(제목 · 알림 · 카드 · 띠)은 끝 프레임과 다음 첫 프레임의 자리 · 크기 · 비율 · 줄바꿈이 같아야 한다. 자주 생기는 원인과 막는 법:
    - 정렬 · 상자 폭이 전환 순간 바뀐다 (가운데 → 왼쪽 정렬, 폭 고정 → 글자 폭) → 상자를 처음부터 글자 폭으로 두고, 가운데 맞춤은 상자 자리(left 50% · translate -50%)로만 한다.
    - 글자 크기를 바꿔 옮기면 줄바꿈이 중간에 바뀐다 → 처음부터 도착지 글자 크기 · 폭으로 놓고 scale 로만 키우고 줄인다.
    - 붙어 다니는 조각(머리말 · 아이콘)이 흐름 안에 있다가 빠진다 → absolute 로 띄워 상자 폭에 끼지 않게 한다 (공용 규칙 `> * { position: relative }` 같은 것이 덮어쓰지 않는지 본다).
    - 다음 화면에서 같은 것을 다시 그린다 → 앞 화면에서 잰 자리 · 배율을 넘겨 그 자리에서 시작한다 (모눈 `takeSealGrid`, 알림 `takeSealNote`, 제목 `--tx/--ty/--tw`).
    - 이어받은 크기는 scale 로 늘리지 않는다 (흐려진다). zoom 도 브라우저마다 글자 · 폭 처리가 달라 쓰지 않는다 → 모든 치수를 배율 변수 하나(`--k`, `calc(토큰 × var(--k))`)로 적어 실제 치수로 다시 그린다. 줄일 때만 scale 을 쓴다 (아주 작은 글자 크기는 줄 높이가 반올림돼 비율이 틀어진다).
    - 확인: 전환 전후를 프레임마다 getBoundingClientRect(글자는 Range)로 기록해, 한 프레임 이동이 그 순간 이동 속도와 맞는지 · 끝 자리가 도착지와 같은지 본다. 눈으로 스크린숏 한 장만 보고 넘기지 않는다.
33. **전투 창은 언제나 정사각이다.** 지형(긴 통로 · 가로 통로)의 배치 구역 비율을 그대로 창 비율로 쓰지 않는다 — 창 모양이 지형마다 달라지면 창을 채우는 연출(궁극기 · 신권 대행 컷인, 전투 개시 띠)이 찌그러진다. 창은 긴 변 칸 수에 맞춘 정사각이고, 전장이 좁은 쪽은 가운데 두고 밖은 빈 바탕. 확대해도 창 모양은 그대로이고 안만 잘라 보인다. 아군 · 적이 멀어 창에 다 들어오지 않으면 빈 사이가 아니라 아군 쪽을 비춘다 (app/battle.ts bviewHtml · camFrame · followCamera).
34. **같은 줄의 단추는 같은 크기다.** 한 머리줄 · 도구줄에 놓인 단추(아이콘 · 글자 단추 모두)는 높이가 같고, 아이콘만 있는 단추는 정사각이다 (전체 상세 머리 · 영입 머리 = 36px). 작은 단추(`.small` · `.tiny`)를 같은 줄의 기본 단추 옆에 섞어 높이를 어긋나게 두지 않는다.
35. **누를 수 있는 것과 아닌 것은 모양으로 나눈다.** 창 · 패널 · 노드 표처럼 담는 판은 평평하게(윤곽 · 머리 띠) 두고, 누를 것의 표현 — 선명한 오프셋 그림자(메트로 = 디자인 시스템 shadow-sm: 오른쪽 아래 4px, 가리키면 떠서 6px, 누르면 내려앉음), 가리킬 때 바뀌는 윤곽색 — 을 쓰지 않는다. 그 표현은 단추와 고르는 카드에만 쓴다 (판의 그림자가 안쪽 카드의 '가리킨 색'과 같으면 판까지 단추로 읽힌다). 주 동작은 한 화면에 하나만 다른 모양(갤럭시: 채운 강조색)으로. 메트로는 2026-11-06 사용자 결정으로 주 동작도 일반 단추와 같은 모양이다 (그림자 색만 선택색 복숭아 `--mt-sh-p` — 다음 행동 = 강조색, 카드 안 '선택' 같은 보조 primary 는 잿빛) — 진입 · 닫기 · ✓ · 떠나기 · 계속 같은 단추는 쿠폰일 이유가 없다 (쿠폰형은 css/26-metro.css 주석으로 보존).
36. **선 종류에는 뜻이 하나다.** 점선은 범위 · 미리보기 · 절취선(뜯는 곳)에만 쓰고, 단추 · 판의 테두리를 점선으로 그려 다른 뜻(보조 · 취소)을 담지 않는다 — 뜻을 모르는 표시는 아무것도 알려 주지 못한다. 예외: 업적 도장(메트로)의 점선 고리 — 도장 그림의 일부(우표 · 소인 테두리)라 범위 · 절취의 뜻과 섞이지 않는다 (2026-11-06).
37. **되돌릴 수 없는 조작은 확인 창 한 장으로.** 기물 방출처럼 되돌릴 수 없는 일은 7번(대상 옆 작은 확인)의 예외로, 화면 가운데 확인 창(머리 = 무엇을 · 되돌릴 수 없음 / 몸통 = 바뀌는 것을 이름 + 값 줄로 / 그만두기 · 실제 동작 이름 단추 · ✕)을 띄운다. 메트로는 표가 절취선에서 찢어진 뒤 실행된다.
38. **다시 그리기는 등장 연출을 다시 틀지 않는다.** 서서히 나타나기 · 미끄러져 들어오기 같은 등장 연출은 그 화면 · 덮개 · 창이 처음 열릴 때 한 번만 돈다. 같은 화면에서 단추를 눌러 다시 그릴 때(구매 · 새로고침 · 고르기) 등장이 다시 돌면 화면 전체가 깜빡인다 — 이미 열려 있던 덮개는 `no-in` 으로 건너뛴다 (main.ts render 의 OVERLAYS, 상점 · 순례 2026-11-06). 상태가 실제로 바뀐 그 대상의 연출(8번)만 다시 돈다.
16. **조작은 조작 대상에 붙인다.** 대기석 숨기기 · 보이기는 대기석 자리에, 확대 단추는 보드 옆에. 9번(같은 자리 유지)과 함께: 숨겨도 대기석 자리에 얇은 띠와 같은 단추가 남는다.
17. **이름은 칩이 아니라 제목이다.** 칩(테두리 · 바탕이 있는 알약)은 바뀌는 상태 값(출전 4/4 · 대기 0 · 보유 1)이나 누를 수 있는 것에만 쓴다. 이 화면의 이름(전장 이름 · 지형 틀 이름)은 제목 글자로, 같은 것을 두 이름으로 겹쳐 쓰지 않는다.

## 3. 문장이 맞는 곳 (구조화하지 않는다)

- 서사 · 세계관 · 대사 · 사건 연출 (docs/SCENES.md · VOICES.md)
- 규칙의 **이유**를 설명하는 교범 문장
- 도감의 설명 · 세계관 항목, 결과 보고서의 표 · 그래프
- 고유 효과 한 줄 (반복 수치만 칩으로 빼고 고유 규칙은 짧은 문장으로 남긴다)

억지로 모든 것을 같은 표 · 칩에 넣지 않는다. 비교가 필요한 반복 수치만 구조화한다.

## 4. 만들 때 점검

- 이 화면에서 플레이어가 고르는 것은 무엇인가? 그 판단에 쓰는 값이 문장 안에 있으면 꺼낸다.
- 같은 종류의 값이 여러 화면에 나오면 같은 칩 · 같은 아이콘을 쓴다 (statIc · 자원 아이콘 재사용). 새 시각 언어를 만들기 전에 기존 것을 확장한다.
- 수치는 데이터(config · data)에서 읽는다. 화면에 베껴 적지 않는다 (CLAUDE.md 도감 연동과 같은 규칙).
- 색은 테마 토큰만 (tests/css_check.ts). 숫자는 아라비아 숫자.
- 상태를 바꾸는 단추를 누른 뒤에도 되돌리는 단추가 같은 자리에 보이는가? 스크롤 · 접힘 · 화면 폭을 바꿔 확인한다.
- 강조 테두리가 주변 칸 · 기물 테두리보다 굵지 않은가? 계속 움직이는 것은 시간에 따른 위험 · 진행뿐인가?
- 점선 · 경계선은 1px, 대상의 종류색(흐리게)으로 그리는가? (메트로는 절취선 하나만 `--mt-perf` 1.5px 점선 — 구분선은 실선) 열린 · 꺼진 상태 같은 '비어 있음' 표시는 덩어리 바깥 변에만 둔다. 테두리가 없는 요소에 `border-style` 만 주지 않는다 — 브라우저 기본값(3px · 글자색 흰 점선)으로 굵게 그려진다.
- 보는 대상과 쥔 도구가 같은 강조로 섞이지 않는가? 상태색이 등급색(초록 = 희귀 등)과 겹치지 않는가?
- 누를 때와 끌 때의 표현이 같은가? 조작 단추가 그 대상 옆에 있는가?
