### 지표
- **lift**: 같은 (페이즈, 노드 유형) 평균 승률 대비 승률 차이(%p). 예를 들어 6페이즈 보스는 평균 47%이므로, 보스전이 많은 시너지가 손해를 보지 않는다. ± 는 **런 단위 군집 표준오차 × 1.96** (같은 런의 전투끼리 묶어 계산, 전투를 독립으로 보는 것보다 넓다).
- **패배율 배수**: 실제 패배 수 ÷ 평균으로 기대한 패배 수. 1.00이 평균이고, 0.70이면 패배가 30% 적다. P1~2는 거의 다 이기는 구간이라 lift가 작게 찍히므로, 초반과 후반을 비교할 때는 이 값을 쓴다.
- **클리어율 구간**: 윌슨 95% 구간.
- **기여 지수**: 같은 페이즈 기물 1명 평균 대비 전투당 피해 · 회복 · 보호막 · 받은 피해 배율 (1.00 = 평균).
- **기물 코스트**: 게임에 기물 코스트나 등급 구분이 없다 (일반 51명, 그중 아문센 · 데미우르고스는 시작 불가에 영입 확률도 낮다. 그 밖에 사건 전용 6명). 그래서 **전투 유형(역할)별 평균 대비**로 정규화했다 (`역할 대비` 열).
- **장비 슬롯**: 기물당 3칸 공용이라 슬롯 구분이 없다. **역할(주요 능력치 조합)** 기준으로 묶었다 (생존 = 생명 · 방어, 화력 = 전투 · 민첩, 기술 · 치명 = 기술 포함, 혼합 = 나머지).

### 읽기 전에 (신뢰도)
1. **봇은 시너지 2단계에 거의 못 간다.** 2단계 도달은 시너지당 런의 0.1~3%다. 전체 런 지표는 사실상 **1단계 성능**이고, 2 · 3단계 성능은 고위험 고정 조합 결과로 본다.
2. 기물 lift에는 그 기물이 속한 시너지 효과가 섞여 있다. 시너지 lift에도 같이 출전하는 기물 효과가 섞여 있다. **시작 기물 클리어율**만 무작위 배정이라 인과에 가깝다. 다만 기물당 표본이 약 130런이라 ±7~8%p다.
3. **끝까지 보유 클리어**는 생존 편향이 있다 (오래 산 런일수록 보유 기물이 많다). 참고용으로만 본다.
4. 기물 49명을 한꺼번에 비교하므로, 우연만으로도 2~3명은 ±2σ 밖에 나온다. 순위 경계 근처(종합 z ±1 안쪽)의 차이는 의미를 두지 않는다.
5. 봇은 [정비](포탑 장비)를 고르지 않는다. 데미우르고스 · 아문센은 영입 확률이 낮아 런 표본이 0이고, 사건 전용 기물은 출전 44~450전이다. 이들은 순위에서 뺐다.
6. 고위험 조합은 희귀 장비 2개 고정, 페이즈별 고정 등급, 기존 전장 5곳 기준이다. 신규 전장 8곳은 포함하지 않았다.

## 부록 C. 재현 명령

```bash
# 빌드 (스크래치 폴더에서)
npx esbuild tests/balance.ts --bundle --platform=node --format=cjs --outfile=balance.cjs
npx esbuild tests/balance_meta.ts --bundle --platform=node --format=cjs --outfile=meta.cjs
npx esbuild tests/buildsim.ts --bundle --platform=node --format=cjs --outfile=buildsim.cjs

# 1) 전체 런 1,600판 (워커 4개 × 400판, 반사실 6%, 위험 0, detail = 런 단위 기록)
for w in 0 1 2 3; do node balance.cjs $((1+w*400)) 400 0.06 0 detail > parts/part$w.json & done; wait
node meta.cjs "$(장비 id 목록 JSON)" > meta.json
python3 tests/balance_report.py parts meta.json report_data.json

# 2) 고위험 후반 58조합 (조합당 600전)
for w in 0 1 2 3; do BS_FIELDS=swarm,crimson,sparta,petra,waste node buildsim.cjs comps tests/buildsim_comps.json $((w*15)) $((w*15+15)) 30 0 8 > hr$w.json & done; wait   # → hr.json 으로 합침

# 3) 포탑 장비 11종 × 2조합 (조합당 600전)
for w in 0 1 2 3; do BS_FIELDS=swarm,crimson,sparta,petra,waste node buildsim.cjs comps tests/buildsim_turret_comps.json $((w*6)) $((w*6+6)) 30 0 8 > tur$w.json & done; wait   # → turret.json

# 4) 집계 → docs/balance_report.json
python3 tests/balance_summary.py parts meta.json report_data.json hr.json turret.json docs/balance_report.json
```

- 소요: 4코어 기준 전체 런 약 7분, 고위험 약 8분, 포탑 약 4분.
- 이번에 고친 테스트 도구:
  - `tests/balance.ts`: detail 모드에 시너지 단계 · 장비 키를 추가 (런 단위 군집 오차 계산용)
  - `tests/buildsim.ts`: comps 출력에 조합의 활성 시너지 (인원, 단계)를 추가
  - `tests/balance_meta.ts`: 기물 기본 주요 능력치 · 사거리 · 스킬 이름 추가
  - `tests/balance_summary.py` (새 파일): 오차 · 분류 · 표 집계
  - `tests/buildsim_turret_comps.json` (새 파일): 포탑 장비 비교 조합
