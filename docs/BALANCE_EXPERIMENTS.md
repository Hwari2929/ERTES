## 0. 측정 경로 확인 (tests/balance.ts)

`tests/balance.ts`는 실제 `buildBattle` 대신 `makeBattle`(85행)로 전투를 구성했다. 이 경로는 `build.ts` 내부의 **포탑 자리 · 포탑 장비 · 무휼 자리**(WeakMap)를 넘기지 못해, 포탑이 편성 화면 기본 자리가 아닌 '대표 엔지니어 근처 가장자리'에 설치되고 포탑 장비가 빠진다.

| 계약 후보 봇 | 227 → 222 | 7 · 2 (0.18) | 36 | 35 (엔지니어 런 56개 중 62%) |

- 전체 클리어 차이는 유의하지 않지만 **엔지니어 런은 62%가 다른 결과**를 낸다. 그래서 실제 전투를 `buildBattle(run, enc, false)`로 바꿨다 (이번 실험 전부 이 경로).
- 반사실(시너지 하나 끄기)은 인원 덮어쓰기가 필요해 `makeBattle`을 계속 쓴다. 대신 '켠 상태'도 `makeBattle`로 다시 돌려 같은 경로끼리 비교하게 고쳤다 (이번 실험은 반사실 0%).

- 측정: 청라 우선 봇(`chr`), 위험 0, 시드 1~2400. **P6 보스 첫 진입 직전** 인과율로 단계를 센다 (최종 보스 승리 보상 제외). P5 진입은 5페이즈 1번째 전투 직전 값.
- '청라 7명 런' = 런 중 청라 3단계(7명)에 닿은 런 (2400런 중 200런). 봇 장비 정책은 그대로다 (인과율은 출전 아군 전체 장비 점수 합).

## 9. 측정 방법

- 전체 런: `tests/balance.ts`, 위험 0, 시드 1~800. 기본 봇(시작 기물 무작위 4명)과 계약 후보 봇(`pool`). `detail`로 런 단위 기록을 남겨 lift를 런 군집 오차로 계산했다. 반사실 0%.
- 7번: 위험 6, 시드 1~600, 두 봇.
- 고정 조합: `tests/buildsim.ts comps`, 위험 9, 전장 5곳(swarm · crimson · sparta · petra · waste) × 5 · 6페이즈 × 시드 30. 역경 · 보스만 세어 600전 (BALANCE_REPORT 1-4와 같은 방식).
- 무휼: `tests/balance.ts … chr`, 위험 0, 시드 1~2400. 런 기록에 페이즈 보스 첫 진입 직전 인과율(`kb`) · 청라 최고 단계(`chrMax`)를 추가했다.
- 지표
  - 클리어율 95% 구간: 윌슨.
  - 같은 시드 전환: 기준선 성공 → 변형 실패(S→F), 반대(F→S). p = 부호 검정 (양측 정확 이항). 고정 조합은 (전장, 페이즈, 시드, 노드) 단위로 짝짓는다.
  - 보스 외 · 보스 승률: 전투 단위, 오차는 런 군집. 보스 승률에는 6페이즈 보스 재도전이 들어간다.
  - 평균 도달 페이즈: 런 종료 시 페이즈 (클리어 = 7). 차이 ± 는 같은 시드 짝 차이의 95%.
  - lift: 같은 (페이즈, 노드) 평균 승률 대비 승률 차이(%p), 같은 판 안에서 계산. ± 는 런 군집 표준오차 × 1.96.
- 한계: 봇은 정비(포탑 장비)를 고르지 않고 시너지 2단계 도달이 드물다. 사냥꾼 2단계 · 엔지니어 2단계 lift는 11~26런뿐이다. 성도회 · 테슬라는 고정 조합 1~2개로만 쟀다.

```bash
# 작업 사본 (기준 5c2ad65 + 이 패치), 결과 폴더 X
git worktree add wt 5c2ad65 && cd wt && git apply exp.patch && ln -s ../ERTES/node_modules node_modules && cd ..
mkdir -p X/b X/runs X/comps
npx esbuild wt/tests/balance.ts  --bundle --platform=node --format=cjs --outfile=X/b/bal_base.cjs
npx esbuild wt/tests/buildsim.ts --bundle --platform=node --format=cjs --outfile=X/b/bs_base.cjs

# 변형 번들: src · tests 를 복사한 사본에서 한 줄만 바꿔 같은 방식으로 bal_<id>.cjs · bs_<id>.cjs 를 만든다
#  v1_eng   src/engine/build.ts    TURRET_INHERIT = [1.5, …]           → [1.8, …]
#  v2_hunt1 src/data/synergies.ts  HUNTER atkSpd T(t, [0.15, …])       → [0.2, …]
#  v3_hunt2 src/data/synergies.ts  HUNTER hp T(t, [0, 0.02, …])        → [0, 0.025, …]

cd X
run4() { local d=$1 b=$2 s=$3 c=$4; shift 4; mkdir -p runs/$d; local q=$((c/4)); for w in 0 1 2 3; do node b/$b.cjs $((s+w*q)) $q 0 "$@" > runs/$d/part$w.json & done; wait; }

for v in base v7_d6; do run4 ${v}_d6def bal_$v 1 600 6 detail; run4 ${v}_d6pool bal_$v 1 600 6 pool detail; done
for v in base cA_top60 cB_pow16; do run4 ${v}_chr bal_$v 1 2400 0 chr; done

export BS_FIELDS=swarm,crimson,sparta,petra,waste
#  base 0~8 · v1_eng 0~4 · v3_hunt2 1 2 5 · v5_tesla 6 7 · v6_sir 8
node b/bs_<변형>.cjs comps comps_sel.json <i> <i+1> 30 0 9 > comps/<변형>_<i>.json
```
