# 사건 연출 작성 가이드

사건 본문과 선택 결과를 미연시(비주얼 노벨)식 대본으로 적는다. 규격은 `src/data/scene.ts`, 예시는 `src/data/scenes/pilot.ts` (시범 5편, 톤의 기준).

## 파일 구조

- `src/data/scenes/<묶음>.ts` 가 `<묶음>_SCENES: Record<사건 id, EventScene>` 와 `<묶음>_REG: SceneReg` 를 내보낸다.
- 새 NPC · 배경 · 배경음 · 효과음은 그 묶음의 `_REG` 에 등록한다 (공용 등록부 `scene.ts` 의 키와 겹치지 않게, 기존 키는 재사용 권장).
- 작성 도우미 (`./dsl`): `N(서술)`, `S(화자, 대사)`, `T(화자, 속마음)`, `SUB` (동적 조연 자리).

## EventScene

```ts
{
  cast: ['주연 기물 id', ...],          // 보유 여부와 무관하게 등장. 1~2명
  scene: [ ...본문 15~25줄, SUB ... ],   // SUB 는 본문 중간에 정확히 1번
  subs: { 기물id: [2~5줄], ... },        // 조연 후보 4~6명 (주연 제외)
  after: [ 선택지0 결과, 선택지1 결과, ... ], // 선택지 순서대로. 결과가 갈리면 { 키: [...], 키2: [...] }
}
```

- 결과가 확률 · 조건으로 갈리는 선택지는 키별 장면을 쓰고, 해당 선택지의 `apply` 안에서 분기마다 `api.outcome('키')` 를 호출한다 (기존 효과 코드는 바꾸지 않는다).
- 결과 장면에서 런마다 달라지는 이름(무작위 기물 등)은 `api.outcome('키', { 변수: 값 })` 으로 넘기고 텍스트에 `{변수}` 로 쓴다. 기물 이름은 그 파일의 이름 함수(`nm(u)`, `who(u)` 등)를 쓴다.
- 결과 장면이 필요 없는 선택지는 `null`.

## 줄 (Beat)

| 필드 | 용도 |
|---|---|
| `who` | 화자: 기물 id · NPC id. 없으면 서술 |
| `name` | 표시 이름 덮어쓰기 (`'???'`, `'라스무스 (덕트 밖)'`) |
| `think` | 속마음 독백 (`T()` 가 넣는다) |
| `face` | `base smile grin laugh serious angry sad surprise worried tired smug shy blank` |
| `at` | 화자 위치 `L C R` (처음이면 등장). 보통 주연 L, 상대 R, 조연 C |
| `stage` | 말하지 않는 인물 배치 `[{ id, at, face }]` |
| `exit` | 이 줄 뒤 퇴장 (`true` = 화자, 배열 = 지정) |
| `bg` · `bgm` | 배경 · 배경음 전환. 본문 첫 줄에 반드시 `bg` 와 `bgm` |
| `sfx` | 효과음. 장면당 2~4개 정도, 남발 금지 |
| `fx` | `shake flash fade dark glitch`. 결정적 순간에만 |

## 문체

- **서술은 3인칭 현재형**("~한다", "~이다"). 결과 장면은 과거형도 허용. 문장은 짧고 구체적으로. 감각(소리 · 냄새 · 온도 · 빛)을 하나씩.
- **독백은 주연의 속마음**(1인칭, 반말 독백체). 그 인물의 과거 · 신념 · 버릇과 사건을 잇는 한두 문장. 주연 외 인물의 독백은 드물게.
- **대사는 따옴표 없이** 적는다. 인물마다 말투를 지킨다 (로어 문서의 인용구 · 말버릇 · 존댓말 여부).
- **한 줄 = 1~3문장.** 화면 한 장에 들어갈 호흡. 본문 15~25줄, 결과 3~6줄.
- **주인공**은 `{pc}` (현재 '지휘관')로만 가리키고 대사를 주지 않는다. 인물들이 {pc}에게 말을 걸 수는 있다 (결정은 {pc}에게 맡긴다는 식으로 선택지로 넘긴다).
- 본문 마지막 2~3줄은 **선택지로 자연스럽게 넘어가는 대사**로 끝낸다. 선택지의 내용(효과)을 인물의 말로 암시하되 수치는 말하지 않는다.
- 기존 `text`(요약)의 사실 · 고유명사 · 인용 대사는 모두 장면 안에 살린다. `text` 필드 자체는 바꾸지 않는다 (도감 · 문서용 요약).
- 유머는 인물에서 나온다(버릇 · 집착 · 관계). 설명조 금지, 말장난 과용 금지.
- 로어와 모순되는 설정 금지. 로어에 없는 작은 설정(과거 일화 등)은 써도 되지만 최소한으로, 작업 보고에 목록으로 남긴다.

## 조연 (subs)

- 사건 주제와 가장 잘 엮이는 인물 4~6명. 로어 문서가 있는 인물 우선.
- 2~5줄의 짧은 끼어들기: 조연의 한마디 → (주연 · NPC 의 반응) → 퇴장. 조연 없이 읽어도 본문이 자연스러워야 한다.
- 같은 인물을 여러 사건의 조연으로 쓰는 건 괜찮지만, 묶음 안에서 한 인물이 5회 넘게 나오지 않게.

## 확인

- `npx tsc --noEmit -p .` 통과.
- 화자 id 는 `UNIT_BY_ID` 의 기물 id 이거나 등록부의 NPC id.
